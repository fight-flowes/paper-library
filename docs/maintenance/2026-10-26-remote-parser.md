# cicore01 远程 PDF 解析迁移

## 运行边界

PDF 解析只在 cicore01 执行。本机的网页任务和终端导入统一经 SSH/SCP 调度远端工作器；即使安装了本机 MinerU 或设置了旧的 `PAPER_MINERU_EXECUTABLE`，也不会调用本机解析器。配置不全、SSH 不通、CUDA 不可用、模型不完整及解析失败均报错，不回退。本机不再用 pypdf 提取首页，书目信息核验只读取远端生成的 `pdf-frontmatter.json` 和已有 Markdown。

项目 `.env` 独立保存远程连接配置和凭据，文件权限 0600；运行不依赖 news_processor 配置文件。SSH 校验已知主机密钥，通过本项目独立的 ControlPath 复用连接。临时 askpass 脚本只读取环境变量，密码不进入命令行或日志。

## 远端部署

- Conda 环境：`/home/leisaihua/miniconda3/envs/paper-mineru`。
- 工作目录：`/home/leisaihua/paper-library-parser`。
- GPU：NVIDIA GeForce RTX 5090，约 32 GB 显存。
- MinerU 3.0.9，从工作区源码构建 wheel 安装。
- PyTorch 2.10.0+cu128、TorchVision 0.25.0+cu128，Transformers 4.57.6。
- 从已有环境复制依赖到独立环境，随后仅修改新环境；原新闻环境保持不变。关键解析依赖已对齐原使用版本，完整清单位于远端 `requirements-installed.txt`。
- 模型来自本机已有文件，27 个文件共 3,491,681,953 字节，以 SHA-256 清单核验，不调用本机解析器。
- `worker.py` 对应仓库 `src/paper_library/ingest/remote_worker.py`；部署时需同步该文件、模型清单、机器身份 `deployment.json` 和模型配置 `mineru.json`。

每次任务上传到随机的 `jobs/<32位十六进制ID>/source.pdf`。工作器验证机器身份、安装和模型文件，使用项目自己的 `gpu.lock` 串行解析，生产后端为 `hybrid-auto-engine`，强制使用 CUDA。完成后返回 Markdown、图片、首页信息和解析出处，成功或可连接的失败任务会清理远端暂存目录。

客户端每 5 秒通过 SSH 标准输入发送心跳，远端在输入关闭或连续 45 秒未收到心跳后停止任务，同时检查取消及总超时。工作器跟踪本次任务的子进程及启动身份，包含 MinerU 另起会话的临时 API 服务；退出时仅终止该任务进程，确认回收后释放 GPU 锁。网络不可用时可能保留临时目录。连接恢复后可对已退出任务执行 `worker.py cleanup <ID>`；该操作不会删除仍持有任务锁的目录。不得清理其他项目进程或环境。

本次隔离入库未调用书目信息检索、断段修复和翻译/导读模型，不将解析验收视为所有模型链路验收。

阅读服务、论文包、标注和翻译缓存继续位于本机。模型接口连通性与远程 PDF 解析相互独立。
