## P1：优先修复

### 1. 发布回滚失败会清理掉恢复资料（已复现）

证据：`src/paper_library/ingest/service.py:360-395`。

发布过程中先把活动包和 catalog.tsv 移到备份，再替换新包。如果目录发布失败，进入 except 恢复；若恢复 os.replace 再次失败，finally 仍删除包备份和目录备份。临时故障注入得到：paper_exists=False、catalog_exists=False、package_backup_count=0、catalog_backup_count=0。这是特定 I/O 异常组合下的数据丢失风险，不是说真实库目前已经丢失。

建议：只有提交成功或确认回滚成功才能清理恢复资料；记录明确的提交阶段；启动时识别未完成发布并恢复。另需覆盖进程被强制结束时的恢复：Python finally 不能处理 SIGKILL 或掉电，当前多文件发布不是持久事务。

验收：对每个发布/恢复边界注入异常或终止进程，重启后至少能恢复到一个完整版本，不删除唯一恢复副本。

### 2. Worker 异常可能无声停止，状态页无法发现（已复现）

证据：`src/paper_library/jobs/runner.py:103-139`、`src/paper_library/web/app.py:163-178`。

claim/recover 数据库异常有重试，但 _execute 的异常处理内部再次读取或更新数据库时没有同等保护。异常逃逸后协调线程退出，Web 进程仍活着，systemd Restart=on-failure 不会因此触发。现有 readiness 检查的是目录和数据库，不检查任务线程。

建议：worker 顶层异常保护、可恢复数据库错误退避、独立 worker 心跳/最后成功轮询时间；分别呈现“阅读可用”和“任务处理可用”。无需把可读旧论文一起判定为故障。

验收：任务异常叠加短暂数据库不可用后，线程恢复或被监督重启；状态页在限定时间内显示处理异常。

### 3. 实际网页服务无法定位 MinerU（运行环境已确认）

证据：`src/paper_library/operations/systemd.py:11-22`、`src/paper_library/ingest/service.py:73`。

服务使用指定 Python，但没有设置该 Python 环境的 bin 路径；解析器通过裸命令 mineru 启动。实际读取运行服务的 PATH 并查找命令得到 False，网页状态显示“不可用”；终端 conda 环境检查则显示已安装。

建议：明确配置解析器可执行文件，或把目标环境 bin 加入服务 PATH；启动诊断使用与任务实际相同的命令解析逻辑；增加从生成的 systemd 环境启动的集成冒烟测试。

验收：无需交互式 conda activate，服务可执行 MinerU 版本检查并解析一个小型测试 PDF。此次审查没有触发真实解析。

## P2：可靠性与一致性

### 4. 备份协调和可观测性还不完整（代码确认）

`jobs/workflow.py:75-77` 在整个工作流持有共享维护锁；`storage/backup.py:create_backup` 以非阻塞方式获取独占锁。长任务或持续队列期间定时备份可能反复失败。`operations/health.py:32-39` 只读取清单时间，“已有备份”不表示最近校验成功，也不提示超期。

当前备份在项目内，属于本机恢复副本；不能覆盖磁盘损坏或整个工作目录丢失。历史快照只覆盖四个文本/JSON 文件，不能单独还原历史 images。

建议：备份截止时间、忙时延后和超期告警；记录最近成功校验/恢复演练时间；支持另一磁盘/远端副本；按实际需求提供单篇版本对比和隔离恢复。

### 5. 解析任务缺少阶段超时（代码确认）

`ingest/service.py:97-105` 循环等待解析子进程，只有取消判断，没有最大运行时长。子进程卡住时，心跳仍可能正常，且单 worker 阻塞后续全部任务。

建议：总超时和长时间无进展阈值分别配置；先优雅终止、再杀进程组，保存可重试原因。模型 HTTP 超时不等于整个工作流的时限。

### 6. 命令行配置解析和锁范围不一致（代码确认）

`scripts/_common:10-14` 用 shell source 加载 .env，`config.py:77-89` 使用 dotenv_values(interpolate=False)。两条路径对美元符号、引号、空格等解释不一致，且设置 PAPER_LIBRARY_SETTINGS_FILE 时 shell 仍可能先导出项目 .env 的值，覆盖替代配置。

`cli/guarded.py:14-27` 对所有 library/translate/guide/structure 子命令先锁论文并建快照；list/status/help 等只读操作也可能因写任务而失败；没有筛选参数时会锁全部论文。

建议：一种配置解析入口；按子命令声明读写能力，只给实际写入目标上锁。

### 7. 搜索有漏展示和扩容问题（部分已复现）

`personal/search.py:97-106` 先 LIMIT 段落，再在 routes 中按论文分组，会让命中段落多的论文挤掉其他论文。没有分页，当前论文数只是截断结果中的论文数。

`personal/search.py:47-66` 用整个译文数据库/WAL 的时间作为每篇索引签名；任何论文的译文更新，下一次搜索可能重新索引所有论文；同步发生在请求链路中。

建议：先按论文召回和分页，再展开每篇命中；每篇文档/译文使用独立版本；索引构建移到写入后的增量任务，搜索只查询索引。

### 8. 结构校对与导读没有共享章节模型（数据与代码确认）

阅读页使用 structure annotations（`web/app.py:241-247`），导读 `reading/structure.py:14-43` 直接解释 Markdown 标题。

当前 ws-p0003 两边都是 25 个章节/标题，但比较 id、标题和 level 后存在 2 项差异；不能仅用总数相同判定章节一致。5 篇论文没有结构校对结果，故仍按原始解析展示。导读版本匹配只证明基于当前文字，不证明解释正确。

建议：建立一个包含稳定块 ID、角色和章节关系的文档表示，供渲染、导读、标注和搜索共同使用；显示每篇处理阶段是否缺失/过期；为断段、表格、公式和多栏建立固定质量样本。

### 9. 模型调用缺少跨进程资源治理（代码确认）

翻译的信号量位于进程内，导读、结构和段落修复各自建线程池。单次命令 <=32 不代表同时启动多个命令与后台任务后总并发 <=32。

翻译/导读与结构校对的缓存指纹组成不同；结构包含温度，导读/翻译不包含温度。这可以是缓存保留策略，但需要明确记录生成参数和统一“复用/重新生成”的语义。

建议：按模型端点建立共享并发预算；统一连接复用、错误分类、退避和生成元数据，避免用户以为配置变化已自动作用于旧结果。

## P3：维护与产品完善

### 10. 个人记录仍是单用户、单位置模型

`personal/store.py:66-84` 每篇只保留最后位置；没有多标签页写入顺序保护，较晚到达的旧页面请求可能覆盖新位置。阅读百分比仍依赖页面高度，翻译与导读展开会改变它；离开页面时的保存失败没有重试反馈。

标注目前限于同一原文块；无法直接标注译文或跨段选文，这是实际功能边界。建议先补保存状态、记录时间、写入版本与失效位置处理，再决定是否需要更复杂的阅读统计。

### 11. 发布与测试还不足以保证环境复现

有 248 项 Python 测试和浏览器脚本，但没有发现项目级 Python 依赖锁及 CI 配置。package.json 默认浏览器入口只覆盖 translation，另一个入口是 management；layout/workspace/guide 需要单独执行。当前 src/scripts/tests 下有 54 个未纳入 Git 的文件，审查对象不是一个可直接复现的发布提交。

建议：锁定依赖与解析器环境，统一一条完整验证命令，把故障注入纳入回归；生成可标识、可回滚的发布版本。浏览器模拟解析器测试不能替代真实部署环境冒烟检查。

### 12. 前端基础仍有历史覆盖与可访问性欠账

界面已明显改善，但 reader.css 仍有 1145 行，另叠加 reading-layout.css 与 workspace.css；同一控件样式散落在不同层，前面多次图标不一致是这种组织方式的表现。部分 JS/Python 以密集单行实现，后续审查和局部修改成本偏高。

建议：逐步合并按钮、导航、表单、面板等组件规则，减少覆盖；补键盘焦点、抽屉互斥、长标题、无译文、无结构、窄屏等页面状态测试。保持原文链接/引用的可辨识性，不能为了统一外观全局删除所有下划线。

### 13. 文档、默认配置和界面行为需要同批更新

README 仍有旧描述，例如取消自动翻译后“只执行 MinerU 解析”、研究主题的输入方式以及导入阶段清单缺少结构校对。当前使用 Qwen，而模板默认 DeepSeek；模板与运行选择允许不同，但应明确区分，避免用户误认为模板代表当前运行配置。

建议：每次变更附配置、命令、界面文案、测试更新清单；保留历史审查文件的历史事实，不做全仓盲目替换。

### 14. 部署边界需要保持明确

当前是单用户、本机优先的应用。管理令牌用于请求保护，页面会向允许管理的访问者提供令牌，不是用户登录与权限系统。Web 与任务线程同进程，入口 app.run；systemd 只能监督进程。

若未来共享给他人，需另行设计认证、用户数据隔离、对外访问保护和部署进程模型。当前没有必要为了个人使用拆成微服务，但不能直接把已有管理开关当成多用户权限控制。
