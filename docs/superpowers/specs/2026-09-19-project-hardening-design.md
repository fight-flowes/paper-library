# Paper Library 工程收口设计

## 目标

让论文阅读、翻译、解析和版本管理在干净环境中可复现，并使当前默认模型、缓存来源和译文质量状态透明可控。

## 设计

阅读功能与翻译配置解耦：缺少或损坏 `.env` 时仍可浏览英文正文，翻译命令在真正需要调用模型时才报告配置错误。测试使用独立临时配置，不读取开发机 `.env`。

前端只读取当前默认模型的缓存，不跨模型拼接。缓存记录来源模型、提示词指纹、请求风格、质量警告、完成原因和时间；缓存键按稳定段落内容生成，正文其他位置的修改不再使所有段落失效。旧两列表继续兼容读取，但不会冒充新协议结果。

宽松翻译仍可立即阅读，但带警告的记录可通过 `--retry-warnings` 重试。解析发布以论文库为粒度加互斥锁，避免并发分配重复 ID 或覆盖 catalog。前端完整译文不显示冗余状态，部分或空译文显示状态，译文警告有独立样式。

代码和论文目录作为父仓库中一次明确迁移进行暂存；`.env`、运行缓存和生成报告不入库。README 与实际默认模型、并发、降级策略保持一致。

## 验收条件

- 无 `.env` 时阅读器可启动并浏览英文论文，翻译命令给出清楚配置错误。
- 测试套件不依赖真实 `.env`，在显式指向不存在配置文件时通过。
- 默认 DeepSeek 页面不会混入 Qwen 缓存。
- 修改无关段落后，未改变段落的译文缓存仍可复用。
- 提示词或请求风格变化不会误用旧缓存。
- `--retry-warnings` 只重跑带质量警告的段落。
- 同一论文库只允许一个解析/元数据发布进程。
- Python 测试、浏览器测试和干净配置测试全部通过。
